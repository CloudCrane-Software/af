# §B 返修追加（2026-11-05 · G1 返修批）：symref 命令的**成功**原始输出
# =============================================================================
# 背景（为何要补这一条）：
#   §A 里 `git ls-remote --symref https://github.com/Feasy898/af.git HEAD` 的记录是
#   **exit=124（超时、无输出）** ⇒ §A 的留存原始读数**不支持**任何「默认分支 = main」的引用。
#   事实本身为真：复核员亲跑同一条命令 = exit 0、输出 `ref: refs/heads/main	HEAD`。
#   本条 = 该命令的**成功**原始输出（首次超时、复跑成功 = 如实留痕；**§A 原记录一字未删**）。
#
# ★ 命令形态差异（如实登记，不含糊）：
#   本条走 remote **别名** `github`：`git remote -v` → `github  https://github.com/Feasy898/af.git`
#   ⇒ 与 §A 的直连 URL 是**同一个仓**；差别在仓内 `remote.github.proxy=http://100.64.0.8:7890`
#   （仓内配置）生效 ⇒ 直连 URL 形态在本机**无 proxy ⇒ 仍超时**（下方「复跑直连 URL」条为证）。
#   复跑直连 URL 形态（原始 §A 同款命令）：`timeout 60 git ls-remote --symref https://github.com/Feasy898/af.git HEAD`
#   ⇒ exit=124（超时无输出，与 §A 一致）。
#
# 结论（供 .github/workflows/f1.yml 注释与 README §2.3 引用）：
#   ① GitHub 披露镜像的默认分支 = `main`（symref 实证，exit 0）；
#   ② 分支全集 = **24**（§A 的汇总也写 24 —— §A 的 `--heads` 全量清单 24 行与本条一致）；
#   ③ 含 `product/main` 的分支数 = **0** ⇒ GitHub 侧不存在 `product/main`。
# =============================================================================
